С чего запускается автоматизация

Trigger отвечает на вопрос «когда начинать?». Для учебного старта подходит Manual Trigger. Для события — Form Trigger или Webhook. Для периодической проверки — Schedule Trigger или узел, опрашивающий источник данных.

СитуацияЧто выбрать
Репетиция и отладкаManual Trigger
Сотрудник заполняет поляForm Trigger
Сервис присылает событиеWebhook
Сводка каждый понедельникSchedule Trigger

Test URL и Production URL у формы

У Form Trigger обычно два адреса. Test URL применяется во время отладки, когда редактор ожидает тестовые данные. Production URL предназначен для опубликованного workflow. Не следует раздавать тестовую ссылку как постоянную.

Важно

Для проверки заполните обязательные поля, но сделайте описание коротким и недостаточным по смыслу. Пустые обязательные поля браузер может не позволить отправить — это проверка самой формы, а не ветки IF.

Запуск по расписанию

Задача «в понедельник собрать дайджест» требует расписания. Уточните часовой пояс workflow и время работы сервера. Если процесс зависит от внешней системы, предусмотрите её недоступность, ограничения частоты запросов и дублирующиеся события.

Мини-практика с формой

  1. Откройте практику веб-формы и скачайте учебный JSON.
  2. Проверьте поля «тема» и «описание», откройте Test URL.
  3. Отправьте полную тестовую заявку, затем слишком короткое, но непустое описание.
  4. Сравните, какую ветку выбрал процесс. Перед публикацией обсудите доступность ссылки и сроки хранения данных.

Проверьте себя

Для чего нужен Production URL?

Для работы опубликованного процесса с реальными обращениями. На этапе настройки и диагностики используйте тестовый адрес.

Почему расписание может срабатывать «не в то время»?

Из-за настроек часового пояса workflow или сервера. Сначала проверьте настройки и журнал запусков.
