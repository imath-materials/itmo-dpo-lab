Выберите один повторяемый результат

Автоматизация начинается не с поиска узла, а с описания повторяющейся работы. Например: сотрудник получает запрос на оборудование, проверяет заполнение и заносит корректную заявку в реестр. У такого процесса есть событие (появилась заявка), данные (тема, аудитория, потребность), правило (достаточно ли сведений) и результат (запись или просьба уточнить).

Запишите результат до открытия редактора. Если его нельзя проверить, процесс пока не готов к автоматизации.

Схема, узел и выполнение — разные вещи

Workflow — схема связанных узлов. Node — отдельный шаг: получить данные, сравнить, преобразовать, сохранить. Execution — один фактический прогон этой схемы. Редактор показывает конструкцию; панель выполнений — что произошло с конкретным набором данных.

Manual Trigger→Учебная запись→IF→Результат

В рабочей среде сначала исследуйте вход и выход каждого узла. Цвет успешного выполнения ещё не означает, что деловой результат правильный.

Первый запуск без внешних подключений

  1. Откройте практику первого сценария и скачайте JSON.
  2. В n8n создайте новый workflow и импортируйте файл. Интерфейс импорта может отличаться по версии; ориентируйтесь на команду Import from File.
  3. Запустите вручную через Execute Workflow. Откройте данные каждого узла и проверьте выбранную ветку.
  4. В учебном узле измените приоритет, повторите запуск. Сравните два выполнения и объясните различие.

Сохранить — ещё не значит запустить по событию

Ручной запуск удобен для разработки. Сценарии с формой, расписанием или webhook требуют отдельной подготовки к работе с внешним событием. В современной документации n8n выделяются действия Save и Publish: после редактирования проверяйте, какая версия процесса опубликована. В разных интерфейсах формулировка может отличаться.

Проверьте себя

В чём отличие workflow от execution?

Workflow — описание последовательности узлов; execution — один её запуск на определённых данных. Один workflow может иметь много выполнений.

Если все узлы стали зелёными, можно ли считать задачу решённой?

Нет. Нужно проверить выход: правильную ветку, запись в реестре, отсутствие лишнего сообщения и соответствие исходной задаче.
