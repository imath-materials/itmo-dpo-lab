Что делает HTTP Request

HTTP Request позволяет обращаться к сервису по сетевому адресу. GET обычно читает данные, POST передаёт данные для обработки или создания записи. Метод, URL, заголовки и тело запроса определяют, что получит внешний сервис.

GET https://example.org/api/rooms?building=A
Authorization: Bearer <НЕ_ПУБЛИКОВАТЬ_КЛЮЧ>

Это иллюстрация запроса, а не действующий учебный endpoint. Настоящие ключи не копируют в публичный JSON или Markdown.

Что означает ответ сервера

КодКак читать в учебном кейсе
200Сервис ответил успешно — но содержимое всё равно нужно проверить
400Запрос неверно сформирован
401Не прошла аутентификация
403Недостаточно разрешений
429Сервис ограничил частоту обращений
500 / 503Возможна временная проблема на стороне сервиса

Код ответа не равен бизнес-успеху: даже при 200 данные могут быть пустыми или неожиданными.

Учётные данные и OAuth

Credential — сохранённая конфигурация доступа. OAuth — один из способов предоставить ограниченные права приложению. В интерфейсе n8n следует выбирать поддерживаемый тип Credential, не вставлять секреты в обычные поля и не передавать их в учебных файлах.

На сервере курса может применяться подготовленный администратором маршрут подключения GigaChat. Его внутренняя конфигурация и адреса не публикуются в открытом справочнике; инструкция выдаётся через LMS участникам с доступом.

Разберите запрос без настоящего API

  1. Откройте основной лонгрид по HTTP и OAuth.
  2. Укажите, что получает HTTP Request: URL, метод, заголовки, тело.
  3. Придумайте, какие проверки выполнит следующий узел при 200, 401 и 429.
  4. Предусмотрите резерв: фиксированные учебные данные вместо недоступного API.

Проверьте себя

Почему 200 OK недостаточно для вывода «всё работает»?

Нужно проверить JSON, обязательные поля и бизнес-результат. Сервер может вернуть успешный ответ без нужных данных.

Что сделать с API-ключом в шаблоне workflow?

Удалить его из экспорта, использовать отдельный Credential и выдавать настройку через защищённый учебный канал.
