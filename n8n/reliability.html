Что означает «обработать ошибку»

Не каждую ошибку нужно скрывать. Есть ошибки выполнения (например, HTTP недоступен), а есть бизнес-исключения (например, заявка пришла без информации). Для второго случая часто достаточно обычной ветки IF.

Для ошибок выполнения n8n предоставляет историю Executions, настройки поведения узлов при сбое и отдельные error workflows с Error Trigger. Такой workflow тестируется не так, как обычный ручной запуск; для него нужен автоматический запуск основного процесса.

Правила работы с данными

  • Используйте синтетические сведения до получения разрешения на реальные данные.
  • Пароли, API-ключи и токены хранятся в Credentials, а не в полях узлов и не в экспортируемых JSON.
  • Не отправляйте чувствительные данные внешней модели без подходящего правового и организационного основания.
  • Предусмотрите ограничение объёма текста, очистку опасных полей и срок хранения выполнения.
  • Письмо может быть подготовлено автоматически, но отправка на реальных адресатов требует отдельного решения о правах и подтверждении.

Проверка качества

Отказоустойчивость начинается с данных

Если неверный вход попал в модель, даже безошибочный HTTP-запрос не делает процесс надёжным. До внешнего вызова проверьте формат входа, необходимость передачи сведений, правила маскирования, права доступа и последствия повторного выполнения.
