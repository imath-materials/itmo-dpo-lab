  1. Откройте импортированный пример

    Используйте 02_form_validation.json или повторите его узлы вручную.

  2. Отправьте корректную заявку

    Тема длиннее трёх символов, описание длиннее десяти. Найдите поле valid.

  3. Отправьте неполную заявку

    Слишком короткое описание проходит через другую ветку. Почему условие сработало именно так?

  4. Проверьте названия полей

    Сравните реальные входные ключи формы с теми, что читает Code. Изменение заголовка поля может сломать обращение к нему.

  5. Сохраните проверенное состояние

    Назовите workflow, сохраните его, сделайте скрин нужной ветки и запишите обнаруженную ошибку.

Часть II. От результата на экране к реестру

После проверки базового примера можно добавить Data Table. Создайте учебную таблицу с полями topic, description, priority, result. Подключайте запись только к ветке «Принято».

Проверьте, что неполная заявка не попадает в реестр, а корректная — попадает. Если прав на Data Table нет, оставьте результат в выходе Code и покажите его в Executions. Это полноценный базовый маршрут обучения, а не техническая неудача.
