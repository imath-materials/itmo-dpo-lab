В n8n узлы передают друг другу элементы данных (items). Почти каждое затруднение в начале обучения связано не с названием узла, а с непониманием, какие поля поступили на вход.

Что такое item и JSON

Новые понятия: item, JSON, expression.

Элемент передаёт данные в поле json. Значение можно прочитать по имени поля, например $json.priority. Встроенный редактор выражений n8n показывает доступные поля из предыдущего узла.

Пример входных данных
{
  "request_id": "TEST-001",
  "topic": "Не работает проектор",
  "priority": "Высокий",
  "contact": "demo@example.org"
}

В отличие от «чата», шаги здесь определены заранее: IF проверяет значение поля, а не просит модель угадать решение.

Практика: импорт и два запуска

Скачайте учебный workflow и выполните его в предоставленной среде n8n. Он не требует почты, API-ключей или таблицы.

01 · Проверка приоритета · JSONТри тестовых входа · JSON
  1. Создайте workflow

    В n8n выберите создание workflow и импорт из файла. Укажите 01_manual_priority.json.

  2. Проверьте связи

    На схеме: ручной запуск → тестовая заявка → IF → две ветки. Ветви не должны сливаться без осмысленного шага.

  3. Запустите высокий приоритет

    Нажмите Execute workflow. После IF должен выполниться маршрут «Оперативное рассмотрение».

  4. Измените исходное значение

    В узле «Тестовая заявка» поменяйте priority с Высокий на Обычный. Запустите снова.

  5. Посмотрите Executions

    Сравните выход каждого узла. Укажите, где впервые изменились данные.

Упражнение: форма вместо ручного запуска

Следующий файл добавляет реальный Form Trigger. Пример не использует внешние сервисы и сохраняет два результата только внутри выполнения: «Принято для ручного рассмотрения» или «Вернуть на уточнение».

02 · Форма и проверка · JSON
  1. Импортируйте пример с формой

    Откройте Form Trigger. У него есть Test URL и Production URL; для занятий используйте тестовый. Если несколько участников работают на одном сервере, задайте собственный уникальный Form Path, чтобы формы не конфликтовали.

  2. Нажмите Execute Workflow

    Откройте Test URL, заполните тему, описание и приоритет учебными данными.

  3. Проверьте короткое описание

    Введите слишком короткое описание и найдите ветку «На уточнение».

  4. Откройте узел проверки

    Почитайте, почему поле valid стало false. Исправьте ввод и повторите.

  5. Не публикуйте форму без проверки

    Рабочий URL подходит только для согласованной публикации; тестовый поток может содержать данные, которые не стоит собирать.

Если версия n8n отличаетсяИмпортируемые JSON — учебные шаблоны, подготовленные по структуре имеющихся экспортов. До использования в группе их необходимо импортировать и выполнить в конкретной версии сервера. Если какой-либо параметр формы изменился, создайте Form Trigger вручную по шагам выше.
