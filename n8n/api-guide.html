Когда нужен HTTP Request

Узел HTTP Request отправляет запрос к внешней системе по её API. В отличие от формы, которая получает данные от человека, запрос может получить данные у сервиса или отправить туда результат. Но наличие URL ещё не означает, что доступ разрешён.

Что происходит, когда подключаем GigaChat API

Пользовательский чат GigaChat и программный API — разные способы использования сервиса. Для API сначала получаем право доступа и временный токен, затем отправляем запрос к модели. С июля 2026 года для новых подключений используется https://api.giga.chat; подробные шаги — в документации разработчика.

Авторизация GigaChat APIСертификаты доверияБыстрый старт API
  1. Подготовьте доступ

    Администратор или преподаватель определяет учебный API-проект и способ передачи прав, не распространяя ключи через страницы LMS или публичные JSON.

  2. Проверьте доверенный сертификат

    Если сервер не доверяет цепочке сертификатов, соединение остановится. Правильное решение — установить нужную цепочку доверия на стороне сервера по согласованию с администратором, а не отключать проверку TLS ради занятия.

  3. Настройте авторизацию

    Для GigaChat получение временного токена и последующие запросы — разные операции. В проекте желательно использовать подходящие credentials или отдельный контролируемый механизм обновления токена.

  4. Сформируйте ограниченный запрос

    Передавайте только обезличенные, разрешённые данные. Попросите модель вернуть структурированный ответ, например категорию и краткое объяснение.

  5. Проверьте выход модели

    Если ответ пуст, неверного формата или не совпадает со списком разрешённых категорий, ветка должна идти на ручную проверку, а не автоматически отправлять письмо.

Безопасность

Не вставляйте API-ключи в код учебного сайта, скриншоты или скачиваемые JSON. GitHub Pages — публичный статический хостинг и не является сервером для хранения секретов.

Проверьте, можно ли решить задачу без LLM: условия, таблицы и шаблоны часто достаточны. К существующим сложным кейсам обращайтесь только после освоения базового workflow.

Два пути подключения GigaChat

В этой программе можно отдельно изучать официальный HTTP/OAuth-маршрут и подготовленное OpenAI-совместимое подключение в университетской инсталляции. Второй путь обычно проще начинающим, но его параметры внутренней сети и порядок создания личного credential публикуются только в закрытом курсе Moodle, а не на открытом сайте.

В обоих случаях API-ключ — секрет: он не вводится в форму GitHub Pages, не хранится в workflow JSON и не попадает в скриншоты. Наличие инструкции не означает, что доступ и лимит уже выданы каждому участнику.
