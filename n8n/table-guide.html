Теперь у корректной заявки появится запись в учебном реестре. Это первый процесс с сохраняемым результатом: запуски не исчезают после закрытия редактора.

Рабочая среда: учебная инсталляция n8n ИТМО ↗ (для входа необходим предоставленный доступ).

Что создаём

Продолжаем сценарий из инструкции «Форма и проверка заявки». После ветки «Принять запись» добавим Data Table, чтобы записывать только корректные заявки. Форма не должна автоматически обещать выполнение запроса — она лишь фиксирует обращение.

Пошаговая настройка

  1. Проверьте права

    В доступном вам учебном проекте найдите раздел Data Tables. Если раздел недоступен или нет права создавать таблицу, используйте резервный маршрут ниже; не работайте в чужом проекте без разрешения.

  2. Создайте учебную таблицу

    Назовите её practice_requests и добавьте поля из таблицы выше. Придерживайтесь простых латинских имён, чтобы избежать несовпадения ключей.

  3. Добавьте узел после принятия записи

    На ветке «Принять запись» создайте Data Table и выберите операцию вставки строки (Row → Insert). Выберите свою таблицу.

  4. Сопоставьте входные поля

    Перетащите значения из панели INPUT или используйте выражения {{ $json.topic }}, {{ $json.description }}, {{ $json.priority }}, {{ $json.result }}, {{ $json.checked_by_human }}. Важны точные имена и типы.

  5. Проверьте результат

    Подайте корректную заявку через Test URL; проверьте, появилась ли строка. Подайте неполную — число строк не должно увеличиться.

  6. Подумайте о повторах

    Повторная отправка одинаковой заявки может создать дубль. Для реального процесса понадобится устойчивый идентификатор и решение: вставлять, обновлять или отклонять повтор.

Ожидаемый результат и резерв

После двух тестов в таблице должна появиться только одна корректная запись. Поле checked_by_human остаётся ложным до фактической проверки ответственным.

Резерв без доступа к таблице

Если Data Table не предоставлена, оставьте процесс на выходе узла «Принять запись» и откройте Executions. Сохраните скриншот входа и результата. Проверка ветвлений остаётся полноценным результатом базового занятия.

Подробнее о тестировании, ошибках и повторах — в разделе надёжности. При работе с реальными заявками требуется согласовать, какие данные разрешено хранить.
