Пошаговая инструкция по импорту, запуску и изменению первого n8n-сценария. На выходе — две проверенные ветки одного процесса. Внешние API и учётные данные не нужны.

Перед практикой

Нужна подсказка по редактору, данным или условию IF? Откройте короткую главу.

Один сценарий должен вернуть «Оперативное рассмотрение» для высокого приоритета и «Общий порядок» для обычного. Источник данных — учебный Code-узел, который уже содержит образец, поэтому писать JavaScript с нуля не требуется.

Инструкция: от импорта до первого результата

  1. Создайте пустой workflow

    Войдите в выданную учебную инсталляцию n8n, откройте доступный проект и выберите создание нового workflow. Назовите его «Практика 01 — приоритет».

  2. Импортируйте JSON

    В меню workflow выберите импорт из файла (Import from File или аналогичный пункт). Выберите 01_manual_priority.json. Проверьте, что на холсте пять узлов.

  3. Проверьте вход

    Откройте узел «Тестовая заявка». Там уже задан вымышленный объект: номер, тема, приоритет, контакт. Посмотрите поле priority, но пока ничего не меняйте.

  4. Запустите процесс

    Используйте Execute Workflow. Проверьте, какой путь выделился на холсте. В узле «Срочный маршрут» найдите поля route и status.

  5. Измените ровно одно значение

    В узле «Тестовая заявка» замените строку 'Высокий' на 'Обычный', не изменяя остальной код. Снова запустите workflow. Теперь должна выполниться вторая ветка.

  6. Объясните результат

    Откройте IF и посмотрите выражение {{ $json.priority }} и ожидаемое значение «Высокий». Сформулируйте своими словами, почему результат изменился.

  7. Проведите проверку границы

    Попробуйте значение 'высокий' со строчной буквы. Уточните, должен ли процесс учитывать регистр, и почему это важно для реального рабочего процесса.

Проверьте не только итоговый текст, но и входное значение IF. Если обе ветки неожиданно ведут в одно место, убедитесь, что вы действительно сохранили изменённый код и запустили workflow заново.

Когда первая схема понятна, переходите к форме с проверкой полей. Там данные будут приходить от пользователя, а не из тестового узла.
