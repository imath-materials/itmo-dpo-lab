На интенсиве важно не количество узлов, а работоспособность и объяснимость процесса. Выберите задачу с понятным событием, полезным результатом и возможностью проверки.

Перед практикой

Выбирайте один работающий сценарий, затем расширяйте его по необходимости.

Собственный проект →Хранение и таблицы →Модели и агенты →
Выбор проекта

Начните с рабочего процесса, который можно продемонстрировать на вымышленных данных: повторяемая операция, определённые входные поля, наблюдаемый результат и контроль ошибок. Допустимые сюжеты не ограничиваются заявками или обратной связью: расписания, дайджесты, учёт событий, проверка данных и согласование материалов также подходят. Если процесс содержит важные решения, оставьте этап подтверждения человеком.

Перед интенсивом полезно пройти разбор процесса, учебную форму и дополнительный материал по API, если он нужен для вашей идеи.

Каталог проектных направлений

01 / базовый

Реестр запросов на оборудование

Форма → проверка полноты → категория и приоритет по правилам → таблица. Сначала без ИИ.

Тест: полная и неполная заявки; повторный ввод.

02 / базовый

Сводка задач по встрече

Записи (заранее подготовленный список) → выделение обязательных полей → список задач с неопределённостями.

Тест: задача без ответственного остаётся на уточнение.

03 / средний

Регулярный дайджест материалов

Расписание / ручной запуск → RSS или подготовленный список → отбор → сводка со ссылками на источники.

Тест: пустая лента и повторный материал.

04 / средний

Контроль готовности мероприятия

Таблица этапов → проверка незаполненных полей → список того, что требует внимания организатора.

Тест: все задачи закрыты и пропущен срок.

05 / продвинутый

Обратная связь по занятию

Чтение уже собранных обезличенных отзывов → обобщение → проверяемый черновик отчёта → согласование человеком.

Тест: пустая таблица; ответ модели вне формата.

06 / продвинутый

Маршрутизация заявок с ИИ

Форма → очистка данных → классификация → реестр → уведомление. При чувствительном тексте — ручная ветка.

Тест: срочная заявка, обычная, содержащая секрет.

Последние два направления основаны на ранее реализованных учебно-демонстрационных процессах. Это ориентиры сложности, а не обязательные задания всем слушателям.

Рабочие этапы интенсива

  1. Постановка задачи

    Определите, что приходит на вход, какой результат нужен и как узнаете, что он правильный.

  2. Минимальный маршрут

    Сначала соберите 3–5 узлов, которые решают базовую задачу без внешних интеграций.

  3. Проверка двух случаев

    Проведите корректный и проблемный ввод; посмотрите путь данных.

  4. Одно расширение

    Добавьте только то, что реально усиливает проект: реестр, расписание, HTTP, уведомление или LLM.

  5. Отказ и восстановление

    Опишите, что произойдёт при сбое и кто сможет вручную продолжить работу.

  6. Защита

    Покажите запуск и результат, объясните ключевые узлы, продемонстрируйте тест и границы использования.

Выберите тип результата, а не количество узлов
